# Development and local pilot

This guide covers the Agents workspace in the public unified repository. The [Skills catalog](catalog/CONTRIBUTING.md) has separate installation and validation instructions. Offline verification is available without credentials; hosted pilot and deployment setup require separate maintainer authorization. Existing production remains on the legacy Agents source until the [cutover](docs/unified-cutover-checklist.md) is complete. Do not enable any of the historical pilot or app setup paths in this repository merely to develop or test locally.

Requires Node.js 24 and the pnpm version pinned in `package.json`. Run `pnpm install --frozen-lockfile --ignore-scripts` before testing the webhook endpoint or running type checks. CI runs the offline tests on push and pull requests.

Vercel build and function installation use Corepack to honor the exact package manager pin. Verify the pnpm version and frozen-install behavior in the authorized prebuilt deployment workflow before promoting a new production revision.

Run `pnpm test` for offline verification. To review a public PR, configure `OPENAI_API_KEY`, `OPENAI_MODEL` (a model supporting structured outputs), and `ODDMASH_ALLOWED_REPOSITORIES` (comma-separated exact repository names) in your environment using your normal secret manager. An optional read-only `GITHUB_TOKEN` raises public API rate limits. Do not commit credentials.

For the hosted pilot, add `OPENAI_API_KEY` to repository Actions secrets, then use Actions → Reviewer pilot → Run workflow on main with an open Oddmash UI PR number. The workflow uses GPT-5.4, anonymous public repository API requests, and report-only output in the job log. It never posts or executes PR code.

For the separate organization reviewer, register an Oddmash-owned GitHub App with Contents read, Pull requests read/write and Checks read. Install only on the public repositories explicitly listed in `.github/workflows/organization-review.yml`. Configure repository variables `REVIEWER_APP_ID`, `REVIEWER_APP_SLUG` and `REVIEWER_APP_ENABLED=true` plus the Actions secret `REVIEWER_APP_PRIVATE_KEY` in the authorized legacy deployment repository. The scheduled workflow scans up to three new review states per execution and never checks out contributor code. Approval requires complete validated coverage, zero findings and passing current checks; actionable high-confidence defects can request changes; incomplete evidence receives a comment instead. The App never merges PRs. Private repositories are excluded until explicitly approved for model data processing.

For event-driven reviews, create a separate fine-grained dispatch token scoped only to `Oddmash/oddmash-agents` with Actions read/write (no Contents write). Store it as `REVIEWER_DISPATCH_TOKEN` in an organization Actions secret accessible only to the five opted-in public repositories. Their trusted event relays dispatch the central workflow with a repository and PR number on PR creation, update, reopen, ready-for-review, and CI completion. No PR code or artifact is executed by a relay. Verify a live dispatch before setting the central variable `REVIEWER_EVENT_MODE=true` to disable the ten-minute fallback scan. Keep the App private key and OpenAI key only in the authorized deployment repository.

Use the API organization linked to the ChatGPT subscription benefit. The initial available promotional balance is USD 97, with no arbitrary USD 10 monthly cap. Prefer review quality while keeping the existing per-request size and output limits. Verify the grant's expiry and disable automatic recharge in API billing before enabling the pilot. Do not add purchased credits or payment methods for this pilot. The application does not read or guarantee the remaining promotional balance; billing controls must be verified separately. Stop on credit exhaustion rather than retrying against another account.

Run `pnpm run review Oddmash/oddmash-ui 24` with an eligible open PR number. The report is printed locally and does not post. Use a read-only GitHub token for this stage. Model calls may incur API charges; only run against an approved public repository.

For the inline comment pilot, explicitly enable `ODDMASH_ALLOW_POST=true`, supply a token scoped to the target repository with pull-request write permission, and add `--post`. In Actions, register this token as `REVIEWER_GITHUB_TOKEN` and select `post_inline` when manually dispatching Reviewer pilot. Use a fine-grained token limited to Oddmash UI with pull requests read/write and contents read, no source write access. Public check results and organization guidance are read without a token; no Checks permission is required for this pilot. Each finding is attached to its actual changed line. A high-confidence localized replacement may appear as a GitHub Suggested change. Suggestions are advisory, not tested patches, and never applied automatically. No approvals or blocking status. Serialize runs per repository/PR to prevent concurrent duplicate comments.

Sensitive patterns and size caps are defense-in-depth, not a guarantee that public content has no private data. Review repository policy before opting in. The service excludes private repositories and does not retrieve workflow logs or artifacts. Source patches are sent to the configured model API, with storage disabled in the request. Do not use report outputs as a sole merge decision.

## Change-aware CI

Open PRs as ready for review by default, even when remote checks are pending. Use a draft only for a documented exception under [organization agreements](https://github.com/Oddmash/.github/blob/main/AGENTS.md), and mark it ready when resolved.

Every pull request keeps a stable `verify` result. Documentation-only and repository-metadata changes run the shared scope check; source, test, package, and CI changes run the offline test suite. Workflow changes also receive syntax validation. Manual dispatch runs the full profile. See [Oddmash CI policy](https://github.com/Oddmash/.github/blob/main/docs/CI-POLICY.md).
