# Agent-readable public documentation

For public libraries, SDKs, APIs and developer tools, provide a maintained `llms.txt` index by default alongside human-friendly documentation. For other public products, add it when an agent has a real task to complete. Follow the evolving [llms.txt proposal](https://llmstxt.org/); do not claim universal crawler support, ranking benefits, or a formal web standard.

- Serve a stable public `/llms.txt` or the appropriate deployed site/docs base path (including GitHub Pages project paths). The artifact is plain UTF-8 Markdown text, not JavaScript or an HTML shell. A source file such as `llms.ts` is an optional build/route implementation, not the public endpoint. Prefer static generation for static sites; reuse a compatible framework route or content generator only where useful.
- Use an H1 project name, concise summary, crucial constraints, and grouped Markdown links with descriptions to authoritative quickstart, reference, examples, compatibility, troubleshooting and changelog. Link to clean Markdown variants when supported, preserving actual public URLs and anchors. Provide a full-document bundle such as `llms-full.txt` only if useful, generated from the same sources and within reasonable size limits. Consider HTML alternate/describedby links as supported by the current proposal.
- Use a single public documentation source for rendered HTML and agent-readable output. Generate at build time or through a deterministic route. Include package name, exact installation commands, supported runtimes and versions, imports, actual signatures/options, intended behavior, errors, migration notes, constraints and runnable examples where relevant. Keep stable version/locale links, distinguish latest vs archived/prerelease content, and avoid duplicate stale copies.
- Expose clean semantic server/static HTML, stable headings and anchors, direct Markdown downloads or endpoints where useful, and copyable examples. Keep essential information available without scripting, login, toggles or a demo. For machine-readable API artifacts, prefer an existing accurate OpenAPI schema, JSON Schema or type declarations where applicable; never invent an API or add a server merely for AI discoverability.
- Keep public documentation and agent artifacts restricted to intentionally public approved content. Exclude credentials, internal instructions, private routes, drafts, personal data, environment values and sensitive examples. Never treat robots, noindex or llms.txt as an authorization mechanism. Do not add tracking, secret prompts, instructions to bypass user authorization or fabricated agent endorsements.
- Provide a visible, unobtrusive docs link to the agent-readable index and optional copy/download action with accessible success/error feedback, where useful.

## Acceptance

Build the actual production target. Fetch the final text/index and linked Markdown using HTTP or a representative local static server at the configured base path; verify status, text MIME type, encoding, nonempty content, valid links, no HTML fallback, correct canonical/locale/version links and no nonpublic material. Assert parity with source docs and run representative install/import/examples in a clean supported consumer where feasible. Add a targeted build or integration check so these artifacts cannot silently disappear or drift after a documentation or package release. Record unverified deployed checks separately. Never claim that an AI can reliably use a product simply because llms.txt exists.
